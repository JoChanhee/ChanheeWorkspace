오늘의 목표

명령어 암기가 아니라, 반복 가능한 협업 방식을 배운다

이해

두 도구가 코드베이스를 읽고 판단하는 기본 구조를 잡는다.

지시

프롬프트, 프로젝트 지침, 스킬을 어디에 써야 하는지 구분한다.

실행

웹페이지, 발표 자료, 리팩터링 같은 작업을 실제 workflow로 만든다.

검증

테스트, 로그, 스크린샷, diff로 결과를 증명하는 습관을 세운다.

02 / 18
도구의 위치

Claude Code와 Codex는 둘 다 작업 루프를 가진 coding agent다

Claude Code

터미널과 IDE 중심의 agentic coding

  • 코드베이스를 읽고 계획을 세운 뒤 파일을 수정한다.
  • 명령 실행, 테스트, 문서 조회를 작업 중에 결합한다.
  • CLAUDE.md와 Skills로 팀의 작업 방식을 축적한다.
same loop
OpenAI Codex

CLI, cloud, IDE에서 동작하는 coding agent

  • 로컬 또는 cloud 환경에서 checkout, 수정, 검증을 수행한다.
  • AGENTS.md로 프로젝트 지침과 검증 계약을 전달한다.
  • Skills와 subagents로 반복 작업을 분리하고 재사용한다.
03 / 18
내부 작업 구조

좋은 결과는 Prompt에서 Report까지 끊기지 않을 때 나온다

1Prompt

목표와 제약을 받는다.

2Context

파일, 문서, 히스토리를 읽는다.

3Plan

작업 단위와 검증 기준을 잡는다.

4Tools

편집, 명령, 브라우저를 사용한다.

5Verify

테스트와 렌더링을 확인한다.

6Report

근거와 남은 리스크를 전달한다.

agent에게 일을 맡긴다는 것은 결과뿐 아니라 판단 근거와 검증까지 위임한다는 뜻이다.

04 / 18
잘 쓰는 핵심

기억해야 할 지침과 필요할 때 꺼내는 절차를 나눈다

Always remember

프로젝트의 build/test, PR 규칙, 금지 사항처럼 매번 필요한 내용.

On-demand workflow

발표 자료 생성, 디자인 적용, 보안 리뷰처럼 특정 상황에서만 필요한 절차.

One-off prompt

오늘 한 번만 필요한 목표, 범위, 예외, 보고 방식.

항상 필요한 것은 프로젝트 지침으로, 반복 절차는 Skill로, 이번 맥락은 프롬프트로 둔다.

Claude memory surface

CLAUDE.md는 Claude Code에게 팀의 작업 맥락을 남기는 곳이다

자주 쓰는 명령, 아키텍처 메모, 코딩 규칙, 주의할 운영 습관을 프로젝트 안에 둔다.

Commands

개발 서버, 테스트, 배포 검증처럼 반복 실행되는 명령.

Architecture

중요한 경계, 데이터 흐름, 피해야 할 shortcut.

Team habits

리뷰 기준, 보고 방식, 작업 전 확인해야 할 파일.

2. Build the artifact.
3. Run visual and overflow verification.

Skill 사용 흐름

좋은 Skill은 agent가 읽을 순서를 설계해 둔다

1Metadata

name과 description만 먼저 노출한다.

2Trigger

명시 호출 또는 설명 매칭으로 선택된다.

3SKILL.md

작업 절차와 기준을 읽는다.

4Assets

필요한 템플릿과 참조만 로드한다.

5Scripts

반복 작업은 스크립트로 실행한다.

6Evidence

검증 결과를 보고한다.

example invocationdeveloper request
$frontend-studio claude 디자인으로 ppt slide html 만들어줘
$skill-creator 반복되는 리뷰 절차를 skill로 만들어줘

예제 1: 웹페이지 만들기

웹 UI 요청은 목적, 사용자, 분위기, 검증을 같이 줘야 한다

  • 사용자가 첫 화면에서 해야 할 일을 명확히 준다.
  • 브랜드, 색, 참고 사이트, 금지할 느낌을 같이 적는다.
  • 구현 뒤 서버를 띄우고 screenshot, mobile, overflow를 확인하게 한다.

예제 2: PPT를 HTML로 만들기

슬라이드는 내용을 붙여 넣는 일이 아니라 화면 밀도를 설계하는 일이다

한 장에 담을 메시지를 줄이고, viewport별로 글자와 카드가 겹치지 않는지 검증해야 한다.

Story

청중이 가져갈 한 문장을 먼저 정한다.

Density

표, 코드, 리스트가 많으면 장을 나눈다.

Viewport

1280x720과 모바일에서 overflow를 직접 확인한다.

실전 적용 전략

팀은 Ask에서 Automate로 천천히 올라가면 된다

Ask

코드 경로와 원인을 물어본다.

Patch

작은 수정과 테스트를 맡긴다.

Verify

증거를 요구하고 재시도하게 한다.

Delegate

독립된 조사를 subagent에 나눈다.

Automate

반복 절차를 Skill과 스크립트로 만든다.

개발자 프롬프트 패턴

좋은 요청은 agent가 판단할 기준을 먼저 준다

Goal

무엇이 완료 상태인지.

Context

관련 파일, 에러, 화면, 배경.

Constraints

건드리면 안 되는 범위.

Evidence

어떤 테스트와 로그가 필요한지.

Report

최종 답변 형식과 언어.

prompt skeletoncopyable pattern
목표: onboarding 버튼이 눌리지 않는 원인을 고쳐줘.
범위: settings-provider와 onboarding flow만 수정.
검증: pnpm build, 관련 테스트, 브라우저 클릭 확인.
보고: 원인, 수정 파일, 테스트 결과를 한국어로 정리.

실패를 줄이는 운영 규칙

결과를 믿기 전에 evidence를 보게 만든다

Diff first

어떤 파일이 왜 바뀌었는지 작은 단위로 확인한다.

Tests and logs

통과했다는 말보다 실제 명령과 핵심 출력을 남긴다.

Screenshots

UI 작업은 desktop/mobile 화면으로 검증한다.

Review scripts

Skill 안의 스크립트는 실행 권한과 네트워크 접근을 확인한다.

Small scope

한 번에 하나의 문제를 고치면 회귀 추적이 쉽다.

No auto-merge

agent 결과는 PR과 리뷰 흐름에서 검증한 뒤 합친다.
