06
Claude lane

탐색 먼저, 계획 다음, 구현은 마지막.

여러 파일이 걸리거나 설계가 불확실하면 먼저 읽고 질문하게 한다. Claude는 선임에게 맥락을 설명하듯 다룰 때 강해진다.

Use when

새 저장소 온보딩, 아키텍처 파악, 큰 리팩터링 범위 산정, 스펙과 문서 초안 작성.

C

Source: Claude Code best practices recommend Explore -> Plan -> Implement -> Commit for uncertain or multi-file work.

07
Claude operating pattern

Claude는 컨텍스트를 잘 주면 선임에게 물어보는 도구가 된다.

Ask codebase questions

이 API가 왜 이렇게 생겼나처럼 원인과 배경을 묻는다.

Reference real files

파일, 스크린샷, 로그, URL로 추상 설명을 줄인다.

Let it interview

큰 기능은 먼저 질문하게 해 빠진 엣지 케이스를 찾는다.

08
Codex lane

Codex에는 완료 조건이 있는 작업을 맡긴다.

Codex는 파일 읽기, 수정, 도구 호출을 반복한다. 무엇이 끝인지와 어떻게 확인할지가 품질을 좌우한다.

codex-run
$read relevant files
$make scoped edits
$run lint / tests / build
$return diff + evidence

Source: Codex prompting docs describe the agent loop and recommend reproducible validation, linting, and smaller focused tasks.

Highest leverage habit

Tests

실패 재현 테스트를 먼저 만들게 한다.

Build

타입체크, 번들, 패키징 명령을 명시한다.

Browser

UI는 스크린샷과 모바일 뷰포트로 확인한다.

Diff

작은 diff를 리뷰하고 위험을 남긴다.

Sources: Claude best practices call verification the highest-leverage habit; Codex prompting docs also stress validation commands.

14
Parallel work

병렬화는 같은 파일을 건드리지 않을 때 효과가 난다.

조사, 리뷰, 테스트 작성, 독립 모듈 수정은 병렬화하기 좋다. 같은 파일을 동시에 수정하면 충돌 비용이 더 크다.

good

문서 리뷰, 보안 리뷰, 독립 패키지 수정

risky

공유 타입, 공통 라우터, 전역 스타일 동시 수정

control

worktree, branch, task ownership을 먼저 나눈다.

Sources: Claude best practices on worktrees/subagents and Codex prompting docs on avoiding two threads modifying the same files.

15
Avoid these

실패는 대부분 모델보다 작업 설계에서 시작된다.

Vague task

증상과 완료 조건 없이 고쳐줘만 준다.

No verifier

테스트, 빌드, 스크린샷 없이 사람이 유일한 피드백 루프가 된다.

Bloated memory

규칙 파일이 길어져 중요한 지시가 묻힌다.

Over-permission

민감한 작업에 무제한 권한을 준다.

Operating principle

Claude로 생각을 선명하게 만들고, Codex로 변경을 증명한다.

좋은 개발자 사용법은 더 많은 AI가 아니라 더 나은 작업 단위, 더 좋은 컨텍스트, 더 강한 검증 루프다.
