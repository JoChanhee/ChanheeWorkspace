문제 제기

같은 춤, 다른 속도

  • 정답과 학생 영상은 길이도, 속도도, 박자도 다르다
  • 1초 늦게 시작하거나, 중간에 느려지거나, 동작을 길게 끈다
  • "몇 번째 프레임끼리 비교하나?"가 가장 먼저 풀 문제

같은 A·B·C 동작이지만 도착 시각이 다르다

춤 비교의 진짜 어려움은 '동작'이 아니라 '시간'이에요. 똑같이 잘 췄어도 0.5초 늦게 시작하면 프레임 번호가 다 밀리죠. 이 시간 차이를 어떻게 맞추느냐가 핵심입니다.
PART 1 · 기초 이론05 / 42
가장 단순한 시도

1:1 프레임 비교는 왜 실패하나

  • 가장 쉬운 방법: 정답 i번째 ↔ 학생 i번째를 그냥 비교
  • 학생이 조금만 밀려도 엉뚱한 순간끼리 비교됨
  • 정답의 "펀치" ↔ 학생의 "준비 중" → 잘 췄는데 큰 오차로 오판
RESULT시작 오프셋·속도 차이에 치명적으로 취약

번호만 맞춘 비교 — 밀리면 전부 어긋난다

그냥 같은 번호끼리 비교하면, 0.5초 밀린 학생은 모든 순간이 어긋나서 '엉망으로 췄다'고 나와요. 사람이 봤을 땐 잘 췄는데 말이죠. 그래서 더 똑똑한 정렬이 필요합니다.
PART 1 · 기초 이론06 / 42
핵심 아이디어

시간을 늘였다 줄였다 하며 맞추기

DTW = Dynamic Time Warping — 시간을 고무줄처럼 휘어 두 춤이 가장 잘 포개지는 대응을 찾는다.

단, 순서는 못 바꾼다(1번 다음엔 2번). 속도만 조절할 뿐.

DTW를 한 문장으로 말하면 '시간을 고무줄처럼 늘렸다 줄였다 하면서 두 춤을 가장 잘 겹치는 지점을 찾는 것'이에요. 순서는 못 바꾸고 속도만 조절합니다. 이 직관 하나만 가져가도 절반은 이해한 겁니다.
PART 1 · 기초 이론07 / 42
재료 ① 거리

두 포즈가 얼마나 다른가를 숫자로

  • 시간을 맞추려면 먼저 "두 순간이 얼마나 다른가"를 수치화
  • 흔한 자: 유클리드 거리 — 관절 좌표 차이를 제곱해 더하고 루트
  • 거리가 작을수록 두 순간의 포즈가 닮았다
d = √( Σ (학생ⱼ − 정답ᵢ)² )

두 점 사이 직선 거리. 관절마다 재서 합친다.

관절별 차이(점선)의 합 → 거리 하나

DTW의 재료는 '거리'예요. 두 포즈가 얼마나 다른지를 숫자 하나로 만든 거죠. 학생 손이 정답보다 멀리 떨어져 있으면 거리가 크고, 딱 겹치면 0에 가깝습니다. 이 거리를 모든 순간 쌍에 대해 잴 거예요.
PART 1 · 기초 이론08 / 42
재료 ② 비용 행렬

모든 순간 쌍의 거리표

  • 정답 i와 학생 j의 모든 조합에 거리를 계산 → 표
  • D[i,j] = 정답 i와 학생 j 포즈의 거리
  • 파란 칸이 이어진 길 = 닮은 순간들이 이어진 길
GOAL이 표의 왼쪽 아래 → 오른쪽 위로, 가장 파란(비용 작은) 길을 찾는다

cost matrix — 어두울수록 닮음(저비용)

정답 프레임과 학생 프레임의 모든 짝에 대해 거리를 재서 큰 표를 만들어요. 파란색(가까움)이 이어지는 자리가 '두 춤이 닮은 길'입니다. 이제 할 일은 이 표의 왼쪽 아래에서 오른쪽 위까지 가장 파란(비용 작은) 길을 찾는 거예요.

핵심 ③ 누적 비용

점화식, 친절 버전

γ(i,j) = D[i,j]
  + min( γ(i−1,j), γ(i,j−1), γ(i−1,j−1) )

이 칸까지 가장 싸게 = 이 칸 거리 + (왼/아래/대각선 중 제일 싸게 온 길)

  • 대각선 = 둘 다 한 프레임씩 전진(정상 속도)
  • 가로/세로 = 한쪽 멈추고 한쪽만 전진(시간 늘이기)

세 방향 중 가장 싼 길을 잇는다

겁먹지 마세요. 이 식은 '여기까지 가장 싸게 오는 법은, 직전 세 칸 중 제일 싸게 온 곳에 현재 칸 비용을 더하는 것'이라는 당연한 말이에요. 대각선으로 오면 둘 다 정상 전진, 옆으로 오면 한쪽이 기다린 거예요. 표를 왼아래부터 채워 올라가면 오른위 칸에 '전체 최소 비용'이 적힙니다.

핵심 ④ 경로

역추적으로 길 복원

  • 표를 다 채우면 끝점 (n,m)에서 거꾸로 "어디서 왔는지" 따라 내려옴
  • 경로 위 점 (i,j) = "정답 i ↔ 학생 j가 짝"이라는 대응표
  • 이게 DTW의 최종 산출물 1호 — 정렬 결과

(n,m) → (0,0) 역추적 경로

표를 다 채운 뒤엔 끝에서부터 '내가 어느 방향에서 왔지?'를 거슬러 따라 내려와요. 그러면 '정답 5번 = 학생 7번, 정답 6번 = 학생 7번...' 하는 대응표가 나옵니다. 이게 두 춤을 맞춘 결과예요.

규칙

경로가 지켜야 할 세 가지

① 경계 조건

시작 (0,0), 끝 (n,m) 고정 — 처음과 끝은 서로 맞물린다.

② 단조성

시간은 뒤로 못 간다. i, j는 줄지 않는다 → 동작 순서 보존.

③ 연속성

한 번에 한 칸씩만. 동작을 통째로 건너뛰지 않는다.

WHY이 규칙들이 "순서는 지키되 속도만 조절"을 수학적으로 보장한다. 규칙을 어떻게 조이느냐가 Part 3의 핵심.
DTW가 막 휘어도 되는 건 아니에요. 세 규칙이 있어요. 시작·끝은 맞물려야 하고, 시간은 뒤로 못 가고, 한 칸씩만 움직여요. 이 규칙 덕분에 '3번 동작을 1번이랑 비교'하는 일이 안 생깁니다. 이 규칙을 어떻게 조이느냐가 Part 3의 핵심이 됩니다.

복잡한 좌표 대신 그냥 숫자로 해볼게요. 정답은 1,2,3인데 학생은 1을 두 번 했어요(머뭇거림). 각 칸은 두 숫자 차이의 절댓값입니다. 0이면 똑같다는 뜻이죠. 다음 장에서 이 표를 따라 최소 비용 길을 찾아봅시다.

손으로 따라가기 (2/2)

경로가 머뭇거림을 흡수

  • 끝점 누적 비용 = 0. 경로가 첫 칸을 가로로 한 번 더 감
  • 학생의 중복 "1"을 시간 늘이기로 흡수 → 자세 거리 0
  • 해석: 포즈는 완벽(거리 0), 시작에 한 박 머뭇(경로 휨=타이밍)
PROOFS12의 경로/거리 분리가 숫자로 증명됨

첫 칸 가로 이동 = 머뭇 흡수

보세요. 학생이 1을 두 번 했지만, 경로가 그 구간을 옆으로 한 칸 휘면서 흡수했어요. 그래서 '자세 차이'는 0으로 나오고, 대신 '경로가 휜 정도'에 머뭇거림이 기록됩니다. 자세는 완벽, 타이밍에만 흠. DTW가 이 둘을 어떻게 나눠 담는지 숫자로 확인한 거예요.

DTW 한 장 정리

거리 재기→비용 행렬→누적 비용→경로 ⟹⏱️ 타이밍🧍 자세

좌표에서 의미로

무엇의 거리를 잴까?

  • DTW의 재료는 "두 순간이 얼마나 다른가" — 그럼 무엇의 거리?
  • 날 좌표만으론 부족: 카메라·체격·화면 속 위치가 섞임
  • 그래서 ① 정규화 → ② 움직임의 의미(운동학 지표)로 비교

춤을 비교한다는 건 결국 '무엇을' 비교하느냐의 문제예요. 그냥 화면 좌표를 비교하면 카메라가 조금만 움직여도 다 틀어져요. 그래서 위치를 정규화하고, 좌표를 '속도·각도·스냅' 같은 춤의 언어로 바꿔서 비교합니다.

개선 ①

신뢰도 게이팅

  • visibility threshold(예: 0.7) 도입
  • 임계 미만은 제외, 짧은 결손은 보간
  • DTW 비용에 양쪽 신뢰도의 최소값을 가중치로
EFFECT깨끗한 신호만 DTW로 → 자세·그루브·파워 모두 안정
# visibility 게이팅 (전처리) for j in joints: if j.visibility < 0.7: j = interpolate(j) # 짧은 결손 # 길면 제외 # DTW 비용: 신뢰도 낮으면 영향 ↓ w = min(ref_conf, tgt_conf)

개선 ②-a

Sakoe-Chiba Band

  • 경로가 대각선에서 폭 r 이상 못 벗어나게 제한
  • |i − j| ≤ r — 너무 먼 짝은 아예 금지
  • 극단적 휨 차단 + 계산량 O(n·r)로 감소
  • 주의: r이 너무 좁으면 정상 속도 차이도 못 흡수 → 튜닝

울타리 치기 — 도망 못 가게

첫 해법은 '울타리 치기'예요. 경로가 대각선에서 너무 멀리 도망 못 가게 띠 안에 가두는 거죠. 정답 5번이 학생 50번이랑 짝이 되는 말도 안 되는 일을 막아요. 보너스로 표의 일부만 계산하니 빨라져요. 다만 띠를 너무 좁히면 정상 속도 차이도 못 봐주니 적당히.

세 번째는 좀 고급이에요. '학생 프레임을 기준으로 한 번씩 공정하게 채점하자'는 거죠. 대신 정답 쪽 일부를 건너뛸 수 있어서, 학생이 안무를 통째로 빼먹어도 못 잡는 약점이 생겨요. 그래서 '같은 춤을 끝까지 따라 췄다'가 전제일 때만 써야 해요. 만능이 아니라 트레이드오프가 있다는 걸 아는 게 중요합니다.

함정 ③

경로 vs 거리 혼동

  • 코드에서 실수로 섞으면: 자세 오류(거리 큼)가 "박자 늦음"으로 둔갑
  • 점검: timing 입력이 오직 경로(잔차)인지 코드로 확인
  • DTW 정렬 입력은 정규화 좌표(x,y) — 운동학 지표 넣지 말 것

거리가 타이밍으로 새면 거짓 피드백

세 번째 폭탄은 개념은 쉬운데 코드에서 자주 터져요. 타이밍 점수에 실수로 '거리'를 넣으면, 자세가 틀린 학생한테 '박자가 늦다'고 엉뚱한 피드백을 줘요. 한 번 코드를 열어서 타이밍은 경로만, 자세는 거리만 쓰는지 확인해보세요. 이거 섞이면 사용자가 영문도 모르고 박자 연습만 하게 됩니다.

함정 ④

lag 평균 평행이동의 거짓말

  • 타이밍 클립이 평균 lag 하나로 영상 전체를 통째로 이동
  • "처음엔 맞다 중간에 늦는" 국소 변화가 평균에 묻혀 사라짐
  • 개선: 평균이 아니라 경로 따라 프레임별 동적 오프셋 + 선형 보간
# ❌ 평균 lag 하나로 평행이동 offset = round(mean(lags)) # → 중간 어긋남이 사라져 거짓 시각화 # ✅ 경로 따라 프레임별 동적 오프셋 for (ref_i, tgt_j) in path: render(ref_i, tgt_j) # +선형보간

동작 클립은 평균도 OK · 타이밍 클립은 경로 필수

네 번째. 타이밍 클립을 만들 때 평균 한 값으로 영상을 통째로 밀어요. 그러면 중간에 늦었다 빨랐다 하는 게 평균에 묻혀서, 클립에선 박자가 맞는 것처럼 보여요. 거짓말하는 클립이죠. DTW 경로는 프레임마다 '몇 칸 어긋났는지'를 다 알고 있으니, 그걸 그대로 쓰면 실제 어긋남이 눈에 보입니다.
PART 3 · 함정 ⑤37 / 42
함정 ⑤

그루브/파워를 DTW 후 계산

  • DTW가 시간을 늘이고 줄이며 원본의 속도·스냅을 손상
  • 증상: "영상은 멀쩡한데 그루브/파워 수치만 나쁨"
  • 개선: 세기·리듬 지표는 DTW 보정 전 원본에서 계산
  • + 그루브/파워의 수학적 정의 문서화·검증

시간을 늘이면 힘이 사라진다

마지막 폭탄. 그루브랑 파워를 DTW로 시간을 비튼 다음에 계산하고 있어요. 그런데 DTW가 시간을 늘이면 날카롭던 스냅이 뭉개져요. 원본의 힘이 사라지는 거죠. 그래서 '영상은 멀쩡한데 파워 점수만 이상한' 현상이 생겼던 거예요. 세기·리듬은 원본에서 재고, DTW는 '같은 순간인지' 맞추는 데만 쓰는 게 맞습니다.

PART 3 · 검증39 / 42
검증 문화

고쳤다 = 검증했다

  • 같은 영상 2개 → 모든 ratio ≈ 1.0, 5종 점수 90+ (재현성)
  • 느리게 춘 버전 → DTW가 흡수해 동기화되는가
  • 앞뒤 여백 버전 → 트림이 정상 작동하는가
  • 필터/penalty 적용 전후를 눈으로 비교 (정성 평가)

✓ 데이터 전략

깨끗한 데이터로 먼저 파이프라인을 세우고, 예외 입력은 촬영 가이드로 사전 차단.

🔁 재현성 도장

같은 입력 → 같은 점수? 통과해야 신뢰할 수 있는 시스템.

고쳤다는 건 '검증했다'는 뜻이어야 해요. 같은 영상을 두 번 넣으면 똑같은 점수가 나오는지, 느리게 춘 영상이 잘 정렬되는지 매번 확인하세요. 그리고 우리는 깨끗한 입력으로 먼저 완성하고, 지저분한 입력은 촬영 가이드로 막는 전략이라는 것도 기억하고요.

핵심 5 Takeaway

오늘 가져갈 다섯 가지

  • 1  DTW = 시간을 늘였다 줄였다 하며 정렬 (순서 보존, 속도만 조절)
  • 2  ⭐ 경로 = 타이밍 / 거리 = 자세 — 절대 섞지 말 것
  • 3  좌표를 정규화 → 운동학 지표로 바꿔 '의미'를 비교 (각도·속도·저크)
  • 4  전처리(visibility)가 전부 — 더러운 입력은 모든 점수를 오염
  • 5  표준 DTW는 함정 — band·weight로 자연스러운 경로를, 클립은 경로 기반으로
딱 다섯 개만 가져가세요. DTW는 시간 정렬, 경로와 거리는 다른 신호, 좌표는 의미로 바꿔 비교, 입력 위생이 제일 중요, 표준 DTW는 그냥 쓰면 위험. 이 다섯이 오늘의 전부예요.
